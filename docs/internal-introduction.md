# CUBRID 구성원에게 소개하는 csql-future

**한국어** | [English](internal-introduction.en.md)

## 내부 공유용 소개 글

**매일 쓰는 csql에 Ctrl+R 히스토리 검색과 CUBRID 전용 Tab 자동 완성을 더해 보세요.**

이전에 실행한 SQL을 찾으려고 터미널을 스크롤하거나, 테이블·컬럼 이름과 SHOW 문법을
매번 확인하고 계신가요? `csql-future`는 설치된 `csql` 앞에 편집기를 더해,
평소 접속 방식으로 쿼리를 찾고 수정하는 작업을 돕습니다.

**Ctrl+R로 전에 쓴 쿼리를 다시 사용하세요.** 테이블명과 조건처럼 기억나는 단어만
입력하면 여러 줄 쿼리도 한 번에 찾을 수 있습니다. 단어 순서와 대소문자를 구분하지
않으며, 검색 결과를 편집기로 불러와 고친 뒤 실행할 수 있습니다. 히스토리는 재시작해도
남고, 완전히 같은 명령은 중복 대신 마지막 제출 시각으로 갱신합니다.
퍼지 검색 스타일로 범위를 좁히되, 실제 매칭은 입력한 검색어를 모두 포함하는 부분 문자열 검색입니다.

**Tab으로 CUBRID 문맥에 맞는 후보를 확인하세요.** `SHOW TABLES`,
`SHOW COLUMNS`, `SHOW INDEX`, `SHOW THREADS` 같은 SHOW 문장부터
`;plan`, `;trace`, `;schema` 같은 세션 명령과 주요 인자까지 지원합니다.
`/*+ ... */`, `--+`, `//+` 안의 CUBRID SQL 힌트 이름도 완성합니다.

**실제 스키마에 있는 이름으로 완성하세요.** 접근 가능한 테이블·뷰 이름과 해당
테이블의 컬럼을 제안합니다. `SELECT e.` 뒤에 `FROM employees e;`가 있는
초안이라면 `employees`의 컬럼을 제안하므로, 이름을 확인하러 다른 화면으로 이동하는
작업을 줄일 수 있습니다.

Linux, Python 3.10 이상, uv와 CUBRID 환경이 있다면 다음 두 명령으로 시작하세요.

```bash
uv tool install git+https://github.com/vimkim/csql-future.git
csql-future -u dba mydb
```

`mydb`는 사용할 데이터베이스 이름으로 바꾸세요. 기존 CSQL 옵션을 사용하며,
필요에 따라 독립 모드는 `-S`, 클라이언트/서버 모드는 `-C`를 지정합니다.
먼저 자주 쓰는 쿼리 하나를 실행하고 Ctrl+R로 다시 찾아 보세요.

앞으로는 별도 `cubrid-language-tools`의 공통 엔진을 활용해
**LSP, VS Code 확장, Neovim**으로 사용 경험을 확장할 계획입니다.
SQL을 실행하지 않는 문법 검사와 **구문 강조**를 함께 제공하고,
이후에는 **CUBRID SQL 포매팅과 편집기 포매팅 연동**까지 발전시키려 합니다.
이 편집기·언어 도구 기능은 로드맵이며, 현재 설치 기능과 구분됩니다.

## 짧은 시연 순서

준비: 조회 가능한 테스트 데이터베이스에 접속하고, 아래의 `employees`와 컬럼 이름을
실제 스키마의 이름으로 바꾸세요. 자동 완성 후보는 접속 사용자에게 보이는 메타데이터에 따라 달라집니다.

| 순서 | 보여 줄 동작 | 전달할 메시지 |
| --- | --- | --- |
| 1 | 평소 접속 옵션으로 `csql-future` 실행 | 기존 csql 접속 흐름으로 시작합니다. |
| 2 | 실제 테이블의 조회 SQL을 여러 줄로 작성해 제출 | 여러 줄 쿼리가 히스토리 한 항목으로 남습니다. |
| 3 | Ctrl+R 후 방금 쓴 테이블명과 다른 단어를 입력 | 순서·대소문자에 관계없이 쿼리를 좁혀 찾습니다. |
| 4 | Enter로 불러온 뒤 조건을 수정 | 검색 결과를 편집한 다음 실행할 수 있습니다. |
| 5 | `SHOW `, `SHOW CREATE `에서 Tab | CUBRID SHOW 문법을 문맥에 맞게 제안합니다. |
| 6 | `;pl`에서 Tab, `;plan `에서 다시 Tab | 세션 명령과 주요 인자를 함께 안내합니다. |
| 7 | `SELECT /*+ RE`에서 Tab | CUBRID 힌트 이름을 제안합니다. |
| 8 | `SELECT * FROM emp`와 `SELECT e.`의 컬럼 위치에서 Tab | 실제 테이블·뷰와 해당 테이블 컬럼을 완성합니다. |
| 9 | 종료 후 같은 디렉터리에서 재접속하고 Ctrl+R | 히스토리가 다음 세션에도 이어집니다. |

완성 중 Enter는 후보를 삽입합니다. 목록이 닫힌 뒤 Enter를 다시 누르면 초안이 제출됩니다.
힌트 이름 시연 후에는 주석과 SQL을 완성하거나 Ctrl+C로 초안을 비우세요.
외부 편집기는 현재도 Ctrl+X Ctrl+E로 사용할 수 있으며, 예정된 Neovim LSP 지원과는 별도입니다.

## 발표할 때 구분할 현재 기능과 계획

현재 기능은 **히스토리·Ctrl+R 검색·여러 줄 편집·SHOW/세션/힌트/스키마 완성**입니다.
검색은 모든 검색어의 부분 문자열 포함 조건이며 오타 보정은 지원하지 않습니다.
힌트 완성은 이름을 대상으로 하며 괄호 안 인자는 직접 입력합니다.

LSP·오프라인 문법 검사·VS Code·Neovim·구문 강조는 계획된 언어 도구 배포 범위입니다.
포매팅은 그 이후 확장 목표입니다. 현재 설치 명령으로 편집기 확장이 함께 설치된다고 안내하지 마세요.
발표 시점의 상태는 [로드맵](roadmap.md)에서 확인하세요.
